# Übungen

Jede Übung ist ein eigenständiges npm-Projekt im Ordner [Exercises](./Exercises) und gehört zu einem Unterrichtsblock. Die Anleitung steht jeweils im `README.md`.

| Nr. | Unterrichtsblock | Inhalt und Lernziele | Anleitung |
| --- | --- | --- | --- |
| 1 | Tooling, Projekt-Setup und Testing-Grundlagen | Toolchain mit Vite+ und npm-Skripten verstehen (`dev`, `check`, `test`, `build`, `e2e`). Fehlschlagende Vitest-Tests lesen, Fehler korrigieren und Grenzfälle als Testfälle ergänzen. Einen Fehler, den Unit-Tests nicht erfassen, im Browser finden und mit einem Playwright-Ablauftest absichern. | [README](./Exercises/01-tooling-setup/README.md) |
| 2 | Modernes JavaScript | ES-Module verstehen: einmalige Auswertung und dadurch geteilter Zustand auf Modulebene. Zustand mit Factory-Funktion und Closure kapseln. Fehler durch flache Kopien und geteilte Referenzen finden und durch unveränderliche Updates ersetzen. Beide Korrekturen mit Unit-Tests abdecken. | [README](./Exercises/02-javascript/README.md) |
| 3 | Async JavaScript und Fehlersuche | Promises mit `async`/`await` parallel (`Promise.all`) und sequenziell ausführen, Unterschied im Network-Tab beobachten, Fehler behandeln. Asynchrone Tests mit einer als Parameter übergebenen Fake-Funktion schreiben, die Zeitpunkt und Reihenfolge der Antworten steuert. Vertiefung: Race Condition durch veraltete Antworten diagnostizieren und mit `AbortController` sowie RxJS `switchMap` und `fromFetch` beheben. | [README](./Exercises/03-async/README.md) |
| 4 | TypeScript, Datenverträge, Laufzeitvalidierung und Zustandsmodellierung | Verstehen, warum eine Type Assertion (`as`) auf externen Daten keine Prüfung ist und Typen zur Laufzeit nicht existieren. API-Daten an der Systemgrenze mit einem Zod-Schema validieren. Widersprüchliche Ladezustände durch eine diskriminierte Union ersetzen und mit `switch` und `assertNever` erschöpfend auswerten. Validierung und Zustandsabfolge mit gültigen und ungültigen Eingaben testen. | [README](./Exercises/04-typescript-validierung/README.md) |
| 5 | Web Platform APIs: fetch, WebSocket, Streaming, JSON, Formulare und Web Worker | Sechs kurze, unabhängige Übungen mit je eigener Musterlösung. `fetch`: `text()` und `json()`, HTTP-Fehler ohne Rejection, Netzwerkfehler, Same Origin Policy und CORS-Header in den DevTools. WebSocket: Upgrade-Handshake, Nachrichten an alle Clients senden. Streaming: HTML und NDJSON in Chunks, `ReadableStream` im Browser zeilenweise lesen. JSON: Verlust von `BigInt`, `Date` und `Set`, Replacer und Reviver. Formulare: JSON und `FormData` senden, Prüfung im Browser umgehen, Prüfung auf dem Server mit Zod. Web Worker: blockierten Hauptthread beobachten, Berechnung in einen Worker verschieben und abbrechen. | [README](./Exercises/05-web-platform/README.md) |
| 6 | SPA-Konzepte: Komponenten, Zustand, Routing und Rendering | Zustand nach Verantwortung einordnen: lokaler Zustand, URL-Zustand, abgeleiteter Zustand, Serverzustand (Laden, Fehler, Daten). Suchbegriff in die URL verschieben und gefilterte Liste berechnen statt speichern. Datenfluss über Props bzw. Inputs nachvollziehen. Clientseitige Detailroute mit Routenparameter ergänzen. Nutzerablauf mit Playwright prüfen. Wahlweise in [React](./Exercises/06-spa-konzepte/react/README.md), [Vue](./Exercises/06-spa-konzepte/vue/README.md) oder [Angular](./Exercises/06-spa-konzepte/angular/README.md); gleiche Konzepte, unterschiedliche APIs. | [README](./Exercises/06-spa-konzepte/README.md) |
| 7 | Styling: Ansätze in React | Dieselbe Komponente in vier Styling-Ansätzen vergleichen (CSS Modules, styled-components, vanilla-extract, Tailwind CSS 4) und in den DevTools sehen, woher das CSS kommt. Custom Properties als Design Tokens verstehen, die ein dunkles Farbschema ohne eigenes CSS ermöglichen. Eine Komponente mit CSS Modules und bedingten Klassen gestalten, danach ein zweites Mal nur mit Tailwind-Utilities, und beide Fassungen vergleichen. Abnahme mit Playwright-Tests auf berechnete Farben. Vertiefung: Container Query und `:has()`, je mit eigenem Test. | [README](./Exercises/07-styling-simple/README.md) |
| 8 | Styling und semantisches HTML | Modernes CSS lesen: Grid, Flexbox, Media und Container Queries, Custom Properties als Design Tokens, `:has()`, Komponentenzustände. Seite schrittweise auf Tailwind CSS 4 umstellen und das Refactoring mit Screenshot-Vergleichen und Playwright-Tests absichern. Stolpersteine lösen, z. B. Preflight, Cascade Layers gegen ungelayertes CSS, `group`-Varianten für den Zustand anderer Elemente, Breakpoints und Werte ausserhalb der Skala, Reihenfolge der Varianten. Natives CSS und Utility-First-CSS vergleichen. | [README](./Exercises/08-styling-advanced/README.md) |
